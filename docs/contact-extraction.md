# ФИО и телефон

HTTP `/rank`, AMQP `process_job` и HTTP `/contacts` используют одну подготовку
документа и один извлекатель `rules-ru-v1`. HTTP-адаптер передаёт исходный файл,
извлечённые контакты и их источники. Конвертация DOC/RTF/TXT выполняется анализатором.

`candidate` содержит четыре nullable-поля. `contact_details` содержит статусы текста,
ФИО и телефона, предупреждения, а для каждого найденного поля — цитату, номера строк
и уверенность `high`/`medium`. Это качественные признаки правил, не статистическая
вероятность. Отсутствующее отчество не достраивается. Заголовки исключаются; ФИО
может занимать до трёх соседних строк в начале резюме. Неоднозначные имена остаются
пустыми. Неизвестное имя с явной меткой ФИО имеет среднюю уверенность и требует
ручной проверки; автоматически сохраняются только результаты высокой уверенности.
Метка `ФИО:` может находиться на отдельной строке перед тремя частями имени.

Автоматически поддерживаются номера из 11 цифр с префиксом `+7`, `7` или `8`,
включая пробелы, скобки и дефисы. Другие форматы, короткие и местные номера
возвращают `phone_status=unsupported`; несколько вариантов — `ambiguous` и `null`.
Отдельная метка `Телефон:` или `Моб.:` относится и к следующей непустой строке.
Метки распознаются как отдельные слова; названия профессий и мобильная разработка
не создают ложную неоднозначность телефона.
Международное автоизвлечение и OCR не включены. Ручной ввод международных номеров
сохраняет прежние правила. Пустой текст даёт `text_status=no_text`; `/contacts`
работает без модели, `/rank` по-прежнему отклоняет документ без достаточного текста.

## Сохранение

Миграция `V6__contact_provenance.sql` добавляет происхождение полей кандидата,
последний результат извлечения у резюме и событие `contacts_recovered`.
Для старых значений происхождение не угадывается: заполненные поля защищены.
Пустые поля можно дополнить, если уверенность высокая и ФИО не противоречит
защищённым данным. Введённые вручную непустые поля получают источник `manual`.
Пустые поля формы загрузки означают неизвестные сведения и разрешают извлечение.
Явно сохранённый в provenance ручной `null` защищён. Машинное значение можно
исправить, только если оно всё ещё совпадает с записанным значением provenance.
Автоматическое извлечение не удаляет существующие значения при отсутствии сведений.

Повторная оценка с `target_resume_id` применяет эти же правила. `candidate_hint`
старого задания повторной оценки считается снимком, а не новым ручным вводом.
Совпадение новых контактов с другим кандидатом требует ручной проверки.
Запись контактов сериализуется до захвата строк и проверки идентичности, чтобы
восстановление и сохранение оценки не захватывали блокировки в обратном порядке.

## Восстановление без скоринга

В карточке кандидата: **Восстановить контакты → просмотр → Применить изменения**.
Источники уже сохранённых полей доступны в блоке **Источники контактов**.

1. `POST /api/resumes/:id/contacts/preview` читает файл из S3, проверяет размер и
   SHA-256 и вызывает `/contacts`. Возвращает найденные значения, `changes`,
   `protected_fields` и `revision`.
2. `POST /api/resumes/:id/contacts/recover` принимает `{ "revision": "…" }`.
   Сервер повторяет извлечение и внутри транзакции проверяет актуальность файла,
   значений и их происхождения. Устаревший просмотр получает 409. Клиент не может
   подменить применяемые значения или цитаты.
3. Меняются контакты, их источники и диагностические данные; при изменениях
   добавляется событие. Оценки, требования, статус скоринга и его lease сохраняются.

По умолчанию адрес `/contacts` получается из `RESUME_ANALYZER_URL`.
Для отдельного адреса предусмотрен `RESUME_ANALYZER_CONTACTS_URL`.
Массовое восстановление старых записей автоматически не запускается.

## Проверка

- Python: `python -m unittest discover -s apps/resume-analyzer/tests -q`
  с `PYTHONPATH=apps/resume-analyzer` и установленными зависимостями анализатора.
- TypeScript и сборка: `npm test`, `npm run build`.
- `npx tsx tests/contact-recovery.integration.ts`: отдельные БД/vhost и временные
  S3-объекты, которые тест удаляет. Нужны настроенные PostgreSQL, RabbitMQ и S3;
  анализатор подменяется HTTP-фикстурой. Проверяются API, защита ручных данных,
  конкурентная правка, коллизия идентичности, повторная оценка и HTTP → AMQP → БД.
- `npx tsx tests/contact-recovery.ui.ts`: проверка карточки и просмотра изменений
  в браузере, API подменяется. `TEST_BASE_URL` задаёт адрес фронтенда.

Регрессия Румянцевой проверяется на синтетическом DOCX с переносом
«Румянцева Дарья\nКонстантиновна» и вариантом без отчества.
