# Приложение подбора кандидатов

Приложения разделены в npm workspaces: React + TypeScript + Vite отвечает за интерфейс, Nginx раздаёт его сборку и проксирует `/api` в Express. Backend обслуживает только HTTP API. Отдельный worker получает задания из PostgreSQL и обращается к анализатору по HTTP; SeaweedFS хранит файлы. У каждого приложения свои зависимости, сборка и Docker-образ. Alabuga Framework подключён локально: CSS, встроенные шрифты, `.af-*` компоненты, `initComponents()` с очисткой при размонтировании. Фирменные логотип и геометрия взяты из `apps/frontend/public/assets`.

[Границы приложений, общие пакеты и независимые сборки](architecture.md).

## Запуск

```powershell
docker compose up -d --build
docker compose ps -a
```

Откройте http://localhost:3000. Если `.env` ещё нет, скопируйте `.env.example` и заполните параметры PostgreSQL, S3 и pgAdmin. Пустой `RESUME_ANALYZER_URL` подключает `resume-analyzer:8000/rank` в Compose. Настройка Ollama и сценарии отказа описаны в [документации сервиса](analysis.md). ClamAV при первом запуске загружает базы; до готовности антивируса загрузка отклоняется с понятной ошибкой. API и интерфейс доступны независимо от готовности антивируса и модели.

Существующие миграции не изменены. V2 добавляет индексы; данные и схема восьми таблиц сохранены. Объекты прежних файлов при замене остаются в хранилище для последующей политики архивирования.

## Первый сценарий

1. На экране «Кластеры и профили» создайте кластер. Код направления задаётся согласно вашей организации: исходная схема не определяет допустимые значения.
2. Создайте активный профиль, заполните образование, опыт, ключевые слова, стоп-факторы и дополнительные требования.
3. На экране «Приём резюме» заполните ФИО и телефон и прикрепите PDF/DOCX до 10 МБ.
   Файл и данные сохраняются независимо от доступности анализа. При недоступном сервисе резюме остаётся в очереди до восстановления; при отсутствии активных профилей ждёт настройки требований.
4. Экран «Обработка» показывает очередь, этапы и события. В случае ошибки доступен повторный запуск.
   На экране видны результаты проверки ранее загруженных резюме и чёрного списка. Для ожидающего резюме указана причина: недоступный анализ, отсутствие активных профилей, приостановка обработки или очередь других резюме. После минуты ожидания причина и время ожидания выделяются отдельно. Журнал показывает результаты действий без технических подробностей хранения.
5. «Распределение» показывает максимальную оценку кластера. Нажатие на заголовок раскрывает профили, на кандидата или рейтинг — карточку с деталями.
6. В карточке доступны резюме, HTML-отчёт, скачивание, открытие в новом окне и печать. DOCX отображается как безопасный текст; PDF — встроенным просмотрщиком браузера. Скачанный HTML-отчёт можно распечатать в PDF средствами браузера.
7. После оценки кандидат переводится в работу, затем в архив. Замена резюме из работы запрещена и фиксируется событием. В доступном или архивном состоянии замена разрешена только с установленным флажком и точным совпадением личности.

## Правила данных

- Пробелы ФИО нормализуются, буквы проверяются при вводе и на API. Поиск дублей нечувствителен к регистру и `ё/е`. Телефоны очищаются; российские `8…` и десятизначные номера приводятся к `+7…`, остальные международные номера — к `+…`.
- Новый кандидат с совпадающим телефоном **или** полным ФИО и другими данными отклоняется как конфликт. Одновременные отправки сериализуются advisory locks по двум ключам личности. Повторная загрузка требует явного подтверждения замены.
- Чёрный список независим: данные копируются, FK или `candidate_id` не добавляются. Активная запись с совпадающим телефоном **или** полным ФИО создаёт предупредительный ярлык. Это консервативное правило расширяет исходный поиск по телефону и ФИО; совпадение требует ручного подтверждения, обработка продолжается. При отключении записи ярлык исчезает, журнал прошлой загрузки сохраняется.
- Только активные профили активных кластеров отправляются обработчику. Требования берутся на момент начала задания. Изменение требований или активности не удаляет старые оценки; пересчёт запускается явно.
- На входе проверяются размер, сигнатура формата, расширение, активное содержимое PDF, вложения и макросы DOCX, размер распакованного архива и ClamAV. При недоступном антивирусе файл не сохраняется. DOCX предпросмотр использует текст, без исполнения HTML или внешних связей.
- S3 и PostgreSQL не образуют общей транзакции: API компенсирует откат удалением загруженного объекта. Если сама компенсация недоступна, в лог пишется ошибка для сверки бесхозных объектов.
- Очередь использует `FOR UPDATE SKIP LOCKED`. Запрос обработчика ограничен `RESUME_ANALYZER_TIMEOUT_MS` (по умолчанию 15 минут); аренда истекает через этот срок плюс одну минуту. Перед сохранением сверяются файл, статус и точная метка аренды; устаревший результат отбрасывается. Все рейтинги и итоговый статус записываются транзакционно. Отказ или неполный ответ обработчика переводит задание в `failed`. При недоступном анализе задания в очереди остаются `pending`.
- CSV выгружает всю базу, кластеры и профили, содержит UTF-8 BOM и защищает от формул Excel. Печать таблицы использует текущие фильтры, раскрытие и страницу из 15 кандидатов.

## Обработчик и пределы основы

Worker соблюдает контракт `docs/API_ранжирования_резюме.docx`: `multipart/form-data`, поля `file` и `requirements`, ответ `clusters[].profiles[]`. Проверяются идентификаторы, полнота, отсутствие повторов и диапазон 0–100. Произвольные `details` сохраняются как технические метаданные; пользователю в карточке, отчёте и печати показываются оценка, объяснение, найденные навыки, стоп-факторы и время расчёта.

Основной обработчик `apps/resume-analyzer` извлекает текст PDF/DOCX и оценивает каждый профиль через Ollama. Учитывает общие требования кластера, образование, опыт, ключевые слова, стоп-факторы и комментарии. При стоп-факторе оценка 0. Некорректный ответ, таймаут и отказ модели завершаются ошибкой, частичные результаты не сохраняются. PDF без текстового слоя требует OCR, который пока не реализован.

Анализ выполняется только через `resume-analyzer`. При его недоступности анализ не проводится, остальные функции продолжают работать. Рейтинг и ярлык чёрного списка требуют проверки сотрудником.

Это локальная основа внутреннего приложения; аутентификация, роли, разделение публичной формы и HR-доступа, TLS, аудит пользователей, политика хранения персональных данных и резервное копирование пока не реализованы. Compose по умолчанию публикует сервисы на loopback `127.0.0.1`. Перед публикацией за пределами локального контура потребуется слой доступа.

## Структура

```text
apps/
  frontend/       React, страницы, компоненты, API-клиент, Vite, Nginx
  backend/        HTTP API, загрузка, дубли, антивирус, экспорты
  worker/         очередь и сохранение результатов
  resume-analyzer/ Python API, извлечение PDF/DOCX, агент Ollama
packages/
  contracts/      общие типы, схемы, нормализация и контракт /rank
  data-access/    PostgreSQL, S3, чтение кандидатов и требований
  documents/      безопасное извлечение текста DOCX
db/migrations/    Flyway
tests/            проверки правил и полный сценарий
apps/frontend/public/ предоставленный Framework и бренд
```

## Разработка и проверка

При запущенном Compose:

```powershell
npm ci
npm run dev
npm run build
npm test
npm run test:architecture
npm run test:integration
```

Vite доступен на http://localhost:5173 и проксирует `/api` в Compose на порт 3000. Для другого API задайте `API_TARGET`. `npm run api` и `npm run worker` запускают соответствующие приложения с корневым `.env`. Backend и resume-analyzer в обычном Compose доступны только во внутренней сети; антивирусный порт наружу также не публикуется: для полного потока используйте контейнеры.

Интеграционный сценарий требует работающий Compose и браузер Chrome либо Playwright Chromium. Он создаёт временные записи, проверяет HTTP API, S3, ClamAV, обработчик и UI на широком и узком экране, затем удаляет только созданные им записи и объекты. Артефакты остаются в `.qa`, исключённом из Git. Проверка существующей инфраструктуры: `python scripts/verify.py` (перезапускает PostgreSQL и SeaweedFS).

Контракты реализации сверены с [документацией Vite](https://vite.dev/guide/), [протоколом ClamD INSTREAM](https://docs.clamav.net/manual/Usage/ClamdProtocol.html) и [AWS SDK for JavaScript v3](https://docs.aws.amazon.com/sdk-for-javascript/v3/developer-guide/migrate-s3.html).
