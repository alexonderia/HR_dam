# Приложение подбора кандидатов

[Памятка пользователя](../apps/frontend/src/content/user-guide.md) описывает работу
с интерфейсом, статусы, дубли, рейтинги и действия при ошибках. Она встроена
в раздел `/help` («Памятка пользователя» в меню), доступна без работающего API,
скачивается в Markdown и печатается через браузер. Текст хранится в одном файле
`apps/frontend/src/content/user-guide.md`; страница и скачиваемая памятка используют
этот же источник. После изменения текста пересоберите frontend.

Приложения разделены в npm workspaces: React + TypeScript + Vite отвечает за интерфейс, Nginx раздаёт его сборку и проксирует `/api` в Express. Backend принимает файлы и применяет результаты, worker сохраняет S3 и вызывает `/rank` через временный адаптер. `RABBITMQ_ENABLED` выбирает очередь RabbitMQ либо фоновые файловые задания без брокера. У приложений отдельные сборки и Docker-образы; интерфейс использует локальные ресурсы Alabuga Framework.

[Границы приложений, общие пакеты и независимые сборки](architecture.md).

## Запуск

```powershell
docker compose up -d --build
docker compose ps -a
```

Откройте http://localhost:3000. Если `.env` ещё нет, скопируйте `.env.example` и заполните параметры PostgreSQL, S3 и pgAdmin. По умолчанию приложение работает без брокера через `/rank`; режим RabbitMQ включается флагом `RABBITMQ_ENABLED=true` и Compose-профилем `broker`. [Команды переключения](resume-analyzer-rabbitmq-api.md). ClamAV при первом запуске загружает базы; до готовности антивируса загрузка отклоняется. API и интерфейс доступны независимо от готовности модели.

Существующие миграции не изменены. V2 добавляет индексы; данные и схема восьми таблиц сохранены. Объекты прежних файлов при замене остаются в хранилище для последующей политики архивирования.

## Первый сценарий

1. На экране «Кластеры и профили» создайте кластер. Код направления задаётся согласно вашей организации: исходная схема не определяет допустимые значения.
2. Создайте активный профиль, заполните образование, опыт, ключевые слова, стоп-факторы и дополнительные требования.
3. На экране «Приём резюме» выберите одиночный файл или ZIP. ФИО и телефон необязательны: их извлечёт обработчик. Принимаются PDF, DOCX, DOC, RTF и TXT; ZIP — до 200 документов и 50 МБ, всего до 250 МБ после распаковки.
   Файл и данные сохраняются независимо от доступности анализа. При недоступном сервисе резюме остаётся в очереди до восстановления; при отсутствии активных профилей ждёт настройки требований.
4. Экран «Обработка» показывает очередь, этапы и события. В случае ошибки доступен повторный запуск.
   На экране видны результаты проверки ранее загруженных резюме и чёрного списка. Для ожидающего резюме указана причина: недоступный анализ, отсутствие активных профилей, приостановка обработки или очередь других резюме. После минуты ожидания причина и время ожидания выделяются отдельно. Журнал показывает результаты действий без технических подробностей хранения.
5. «Распределение» показывает максимальную оценку кластера. Нажатие на заголовок добавляет отдельные столбцы профилей в ту же строку шапки. Кандидаты закреплены слева при горизонтальной прокрутке. Нажатие на рейтинг открывает соответствующий кластер или профиль в карточке.
6. В карточке доступны просмотр резюме, отчёт, экспорт и печать с настройками. DOCX, DOC, RTF и TXT отображаются как безопасный текст; PDF — встроенным просмотрщиком браузера. Дата последней обработки указана в начале карточки. Обоснования, совпадения с требованиями и стоп-факторы разделены на блоки.
7. После оценки кандидат находится в статусе «В работе». Когда кластер начинает собеседование или трудоустройство, установите «В процессе». Для архива укажите итог: трудоустроен или отклонён всеми кластерами. Статус меняется на экране обработки и в карточке; кнопка чёрного списка доступна сверху. Журнал упорядочен от новых событий к старым. Замена резюме в процессе отбора запрещена и фиксируется событием. В работе или архиве резюме обновляется автоматически при точном совпадении телефона и ФИО.
8. Кластеры по умолчанию свернуты. Неактивные кластеры и профили расположены после активных. В ключевых словах и стоп-факторах разделителями служат запятые, точки с запятой и переносы строк.

## Правила данных

- Пробелы ФИО нормализуются, буквы проверяются при вводе и на API. Поиск дублей нечувствителен к регистру и `ё/е`. Телефоны очищаются; российские `8…` и десятизначные номера приводятся к `+7…`, остальные международные номера — к `+…`.
- Новый кандидат с совпадающим телефоном **или** полным ФИО и другими данными отклоняется как конфликт. Одновременные отправки сериализуются advisory locks по двум ключам личности. При совпадении обоих ключей замена выполняется автоматически, кроме статуса «В процессе».
- Чёрный список независим: данные копируются, FK или `candidate_id` не добавляются. Активная запись с совпадающим телефоном **или** полным ФИО создаёт предупредительный ярлык. Это консервативное правило расширяет исходный поиск по телефону и ФИО; совпадение требует ручного подтверждения, обработка продолжается. При отключении записи ярлык исчезает, журнал прошлой загрузки сохраняется.
- Только активные профили активных кластеров отправляются обработчику. Требования берутся на момент приёма загрузки. Изменение требований или активности не удаляет старые оценки; пересчёт запускается явно.
- Переход в «В процессе» запрещён при активном совпадении с чёрным списком либо другом резюме этого кандидата с таким статусом. Проверяются идентификатор кандидата, телефон и полное нормализованное ФИО. Интерфейс отключает вариант и показывает причину; API проверяет свежие данные, сериализуя изменения по ключам личности в том же порядке, что и загрузка. Оценка продолжает выполняться; её завершение сохраняет отметку о чёрном списке. При добавлении записи после оценки текущая отметка показана отдельно от исторического сообщения журнала.
- На входе проверяются размер, сигнатура формата, расширение, активное содержимое PDF, вложения и макросы DOCX, размер распакованного архива и ClamAV. При недоступном антивирусе файл не сохраняется. DOCX предпросмотр использует текст, без исполнения HTML или внешних связей.
- Файлы сохраняются в S3 перед анализом. Метаданные файла и кандидат появляются в PostgreSQL после успешного результата в одной транзакции с резюме и рейтингами. Ошибка анализа не удаляет оригинал: его можно отправить повторно. До подтверждённой публикации файл защищён постоянным outbox.
- Задания одиночной и массовой загрузки проходят RabbitMQ. Сначала worker сохраняет файл в S3, затем публикует ссылку для анализа. Backend применяет результаты по одному, в транзакции и с защитой от повторной доставки. Список файлов и статусы импорта хранятся в RabbitMQ; в БД не добавляются поля или таблицы очереди. ФИО и телефон кандидата nullable. [Контракт обработчика и API](resume-analyzer-rabbitmq-api.md).
- Экспорт и печать имеют отдельные настройки: полный отчёт либо только таблица. Форматы экспорта — XLSX, CSV, HTML; PDF сохраняется через печать браузера. Матрица использует текущие фильтры, сортировку, раскрытые профили и все найденные строки независимо от пагинации. XLSX закрепляет кандидатов и шапку; CSV содержит UTF-8 BOM и защищен от формул Excel. В полном CSV представлены строки оценок с обоснованиями. Отдельные полные отчёты кандидатов можно приложить в ZIP или добавить к печати с новой страницы. Настройки доступны также в карточке и открытом HTML-отчёте.

## Обработчик и пределы основы

Текущий HTTP-клиент `/rank` включён временным адаптером в обоих режимах приложения. Нативный AMQP consumer можно подключить позднее. [Переключение режимов и контракт](resume-analyzer-rabbitmq-api.md).

Worker соблюдает контракт `docs/API_ранжирования_резюме.docx`: `multipart/form-data`, поля `file` и `requirements`, ответ `clusters[].profiles[]`. Проверяются идентификаторы, полнота, отсутствие повторов и диапазон 0–100. Произвольные `details` сохраняются как технические метаданные; пользователю в карточке, отчёте и печати показываются оценка, объяснение, найденные навыки, стоп-факторы и время расчёта.

Основной обработчик `apps/resume-analyzer` извлекает текст PDF/DOCX и оценивает каждый профиль через Ollama. DOC, RTF и TXT worker предварительно преобразует в UTF-8 TXT, сохраняя оригинал для скачивания. Учитываются общие требования кластера, образование, опыт, ключевые слова, стоп-факторы и комментарии. При стоп-факторе оценка 0. Некорректный ответ, таймаут и отказ модели завершаются ошибкой, частичные результаты не сохраняются. PDF без текстового слоя требует OCR, который пока не реализован.

Анализ выполняется только через `resume-analyzer`. При его недоступности анализ не проводится, остальные функции продолжают работать. Рейтинг и ярлык чёрного списка требуют проверки сотрудником.

Это локальная основа внутреннего приложения; аутентификация, роли, разделение публичной формы и HR-доступа, TLS, аудит пользователей, политика хранения персональных данных и резервное копирование пока не реализованы. Compose по умолчанию публикует сервисы на loopback `127.0.0.1`. Перед публикацией за пределами локального контура потребуется слой доступа.

## Структура

```text
apps/
  frontend/       React, страницы, компоненты, API-клиент, Vite, Nginx
  backend/        HTTP API, загрузка, дубли, антивирус, экспорты
  worker/         очередь и сохранение результатов
  resume-analyzer/ Python API, извлечение PDF/DOCX, агент Ollama
packages/
  contracts/      общие типы, схемы, нормализация и контракт /rank
  data-access/    PostgreSQL, S3, чтение кандидатов и требований
  documents/      извлечение текста DOCX/DOC/RTF/TXT, кодировки UTF-8/UTF-16/Windows-1251
db/migrations/    Flyway
tests/            проверки правил и полный сценарий
apps/frontend/public/ предоставленный Framework и бренд
```

## Разработка и проверка

При запущенном Compose:

```powershell
npm ci
npm run dev
npm run build
npm test
npm run test:architecture
npm run test:integration
npm run test:workflow
```

Vite доступен на http://localhost:5173 и проксирует `/api` в Compose на порт 3000. Для другого API задайте `API_TARGET`. `npm run api` и `npm run worker` запускают соответствующие приложения с корневым `.env`. Backend и resume-analyzer в обычном Compose доступны только во внутренней сети; антивирусный порт наружу также не публикуется: для полного потока используйте контейнеры.

Интеграционный сценарий требует работающий Compose и браузер Chrome либо Playwright Chromium. Он создаёт временные записи, проверяет HTTP API, S3, ClamAV, обработчик и UI на широком и узком экране, затем удаляет только созданные им записи и объекты. Артефакты остаются в `.qa`, исключённом из Git. Проверка существующей инфраструктуры: `python scripts/verify.py` (перезапускает PostgreSQL и SeaweedFS).

Контракты реализации сверены с [документацией Vite](https://vite.dev/guide/), [протоколом ClamD INSTREAM](https://docs.clamav.net/manual/Usage/ClamdProtocol.html) и [AWS SDK for JavaScript v3](https://docs.aws.amazon.com/sdk-for-javascript/v3/developer-guide/migrate-s3.html).
