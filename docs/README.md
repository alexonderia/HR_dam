# Карта документации HR DAM

Обзор составлен 9 ноября 2026 года. Здесь указано, где искать описание поведения,
архитектуры, запуска и выполненных изменений.

Текущая подготовка приложения относится к **текущему протоколу**: гостевой и
авторизованный режимы, отдельные API, временное и постоянное хранение,
оркестрация prepare/evaluate. Реальные разборщик и оценщик поставляются из
другой ветки; сквозная проверка их реализации выполняется после подключения.

## С чего начать

1. Для запуска приложения — [основной README](../README.md), затем
   [подготовка и включение обработки](preparation.md).
2. Для работы сотрудника — [памятка пользователя](../apps/frontend/src/content/user-guide.md).
3. Для понимания системы — [целевая архитектура](target-architecture.md).
4. Для разработки разборщика и оценщика — [контракт обработчиков](processing-services-contract.md).
5. Для проверки выполненного объёма — [план](implementation-plan.md) и
   [отчёт о подготовке](../reports/application-preparation-2026-11-09.md).

Эти документы полезны для правил предметной области и сопровождения старого
кода. Их технические инструкции про worker, `/rank`, `RABBITMQ_ENABLED` и старые
очереди не описывают текущий запуск обработки.

| Документ | Где и что описано |
| --- | --- |
| [candidate_matching_architecture.md](candidate_matching_architecture.md) | Первоначальная спецификация MVP: восемь бизнес-таблиц, связи и ограничения, статусы кандидатов, сценарий подбора, замена резюме и журналирование. Это не полная схема новой авторизации и задач обработки. |
| [application.md](application.md) | Общее описание приложения, первый сценарий, правила данных, структура исходников и разработка. Описание обработчика, `/rank` и переключения брокера относится к прежней реализации. |
| [analysis.md](analysis.md) | Прежнее подключение Ollama: запуск в Compose или на хосте, модель и память, готовность, ошибки и проверки. Для подключения новых обработчиков использовать `preparation.md` и контракт обработчиков. |

Для parser/evaluator его заменяет `processing-services-contract.md`. |

## Тестовые материалы и точные схемы

- [README фикстур обработки](../tests/fixtures/processing/README.md) объясняет
  синтетические данные и тестовые обработчики, а также границы транспортного
  stub ClamAV. Он не описывает реализацию настоящего разборщика и оценщика.
- [packages/contracts/src/processing.ts](../packages/contracts/src/processing.ts)
  содержит исполняемые TypeScript-схемы протокола обработки.
- [db/migrations](../db/migrations) содержит SQL-миграции фактической схемы БД;
  при работе с авторизацией и задачами нужно учитывать V7, а не только MVP.
- [docker-compose.yml](../docker-compose.yml) и [.env.example](../.env.example)
  задают состав запуска, профили и имена параметров окружения.

При расхождении старых инструкций с текущей схемой используйте текущие документы
`target-architecture.md`, `processing-services-contract.md`,
`guest-task-lifecycle.md` и `preparation.md`, сверяя детали с кодом и миграциями.
