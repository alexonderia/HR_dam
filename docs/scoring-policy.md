# Проверяемые оценки резюме: evidence-v3

Обновлено 16 ноября 2026 года. Новые оценки используют `policy_version=evidence-v3`; семейство формата `method=evidence-v1` сохраняется для совместимости. Сохранённые результаты `evidence-v1/v2` не перезаписываются, их разбиение требований и веса остаются прежними. При открытии отчёта неподтверждённые дополнительные выводы отзываются, а отображаемые балл и диапазон пересчитываются согласованно по исходным весам. Политика остаётся предварительной до независимой проверки рекрутеров. Это оценка соответствия указанным требованиям по доступным сведениям, не вероятность успешного найма и не измерение способностей человека.

## Требования и подтверждения

Критерии создаются программой только из `keywords`, `experience`, `education`, комментария профиля и комментария кластера. Название должности даёт контекст, но не добавляет скрытых требований. Списки навыков разделяются по запятым, точкам с запятой и переводам строк. В опыте, образовании и комментариях явная граница «и/а/но желательно …» отделяет желательное условие от обязательного; слово «желательно» не обнуляет вес соседнего обязательного условия. Каждый критерий имеет стабильный ID и исходное поле. Явно желательные условия (`приветствуется`, `желательно`, `будет плюсом`, `не обязательно`) не дают штрафа и не меняют балл.

Модель возвращает только ID, статус и дословные фрагменты резюме. Модель не назначает балл, список совпадений или объяснение. Неизвестные, повторяющиеся и пропущенные ID ответа модели отклоняются. Цитата проверяется по тексту резюме; в результате сохраняются исходный фрагмент и его границы в Unicode code points. Перед выдачей всего результата источник и цитаты проверяются ещё раз.

В v3 явное «Плюс …» выделяется из комментария в отдельный желательный критерий с весом 0. Например, основное условие про бэкенд высоконагруженных систем и пожелание Kubernetes оцениваются отдельно. Для модели передаются проверяемые факты без метаданных обязательности: желательность меняет вес в программе, а не наличие факта в резюме. Исходная формулировка с пометкой сохраняется в отчёте.

Дополнительные условия проверяются на релевантность цитат: упоминание другой профессии не доказывает бэкенд или Kubernetes, отсутствие технологии не является прямым отрицанием опыта. Применяются консервативные проверки технических названий, контекста бэкенда/нагрузки, отрицаний, намерений, обучения и противоречий. Неподходящая цитата получает один целевой запрос на исправление, затем неподтверждённый вывод становится `unknown`. Входящие v3-результаты независимо проверяет API.

- `met`: соответствие подтверждено цитатой; коэффициент 1.
- `partial`: соответствие подтверждено частично; коэффициент 0,5, кроме числового стажа.
- `not_met`: есть прямое подтверждение несоответствия; коэффициент 0.
- `unknown`: сведений недостаточно или подтверждение не прошло проверку. Это не утверждение об отсутствии компетенции.

Навыки дополнительно проверяются программой по названиям и контексту в резюме с границами слов. Явный `unknown` модели не повышается одним совпадением слова. Намерение освоить навык, желаемая вакансия и стек работодателя не подтверждают владение; текущее обучение даёт частичное соответствие. Явное отрицание не считается совпадением; противоречащие утверждения требуют уточнения; «изучаю»/«базовый» означают частичное подтверждение. Явные алиасы: MS SQL/MSSQL/T-SQL → SQL, RESTful API → REST API. Семантические синонимы автоматически не выдумываются.

Стаж с числовым минимумом, когда ограничивает именно длительность, получает коэффициент `min(подтверждённые месяцы / требуемые месяцы, 1)`. `1–3 года` означает минимум 12 месяцев; 1 год 3 месяца при требовании от 3 лет — 15/36. Явный общий стаж ограничивает максимально возможный релевантный стаж, но сам по себе не доказывает релевантность. Подтверждённые датированные периоды суммируются объединением интервалов без повторного учёта пересечений. Нужны даты не грубее месяца и контекст конкретной релевантной работы; обучение и возраст исключаются. Считаются полные календарные месяцы: неполные граничные месяцы не завышают стаж. Текущая работа ограничена московской датой создания задания (`assessment_date`), одинаковой для повторных доставок. Явная длительность ограничивает период при округлённых датах. При датах только по годам и недостаточной связи — неизвестно. Недатированные длительности по разным работам не складываются, чтобы не задвоить пересечения.

## Формула

Вес категорий: навыки — 40%, опыт — 30%, образование — 15%, прочие требования — 15%. Неуказанные категории исключаются, оставшиеся веса пропорционально нормируются. Внутри категории вес равномерно делится между обязательными критериями. Веса хранятся целыми базисными пунктами, сумма — 10000; остаток распределяется методом наибольших остатков, при равенстве — по ID. Это позволяет одинаково считать результат в Python и TypeScript.

`P = Σ(вес × подтверждённый коэффициент) / 100`.

Для неизвестных критериев отдельно считается возможный дополнительный вклад `U`; обычно это полный вес критерия. Если общий стаж явно ограничивает возможное соответствие требуемому стажу, верхняя граница этого критерия также ограничивается отношением месяцев.

Подтверждённый стоп-фактор вычитает 10 баллов; общий штраф `S` не превышает 30. Один и тот же пункт не штрафуется повторно. Если пробел уже уменьшил оценку соответствующего навыка/стажа/другого критерия, дополнительный штраф за него не применяется. Стоп-фактор должен принадлежать входному списку и иметь проверенную цитату с подтверждением условия. Неизвестное состояние не вызывает штраф. При пустом входном списке результат всегда пуст.

Итог — диапазон `[max(0, P − S), min(100, max(0, P + U − S))]`, округлённый до двух знаков. Поле `score` хранит нижнюю, подтверждённую границу; `details.score_range` — обе границы. Охват `coverage` — доля веса критериев с проверенным статусом, отличным от `unknown`. Если обязательных критериев нет, диапазон 0–100 означает недостаток данных. Сортировка по `score` сравнивает подтверждённый вклад. Основная оценка в интерфейсе, карточках и выгрузках — отдельное число `score`. С 13 ноября 2026 года «Охват критериев» убран из интерфейса и выгрузок; поле `coverage` сохраняется в контракте для проверки результатов. При разнице границ более 20 баллов показывается только подтверждённый балл и пояснение «Недостаточно сведений для полной оценки», а список уточнений раскрывается. При разнице до 20 баллов диапазон сохраняется, при совпадении границ показывается одно число. Это правило отображения, а не сужение исходного диапазона и не изменение формулы оценки. Неполный документ или полное отсутствие подтверждённых критериев также всегда сопровождаются пояснением о нехватке сведений. В компактной матрице используется только основной балл.

С 11 ноября 2026 года подробный отчёт группирует требования по статусам, переданным оценщиком: подтверждено, частичное соответствие и подтверждённое несоответствие. Только явно переданный статус `unknown` отображается как «Не указано»; такие сведения сводятся в короткие строки по категориям, со списком того, что нужно уточнить; он доступен и для старых структурированных оценок. Указанные навыки показаны компактно, с раскрываемыми цитатами. Приложение не определяет заново релевантность опыта, смысл цитат или корректность стажа и не подменяет статусы оценщика. Исходные `score`, диапазон, охват и сохранённый ответ оценщика не пересчитываются. Отображаемое объяснение заново собирается из сохранённых структурированных фактов, поэтому прежний текст об охвате или широком диапазоне не возвращается в карточку. Ошибки фактического анализа исправляются в оценщике. Формула оценки и разбор файлов в рамках изменения отображения не меняются. Старые оценки без `details` показываются с сохранённым пояснением, без выдуманных дополнительных показателей.

Объяснение формируется шаблоном из проверенных сравнений. Оно отдельно перечисляет подтверждённое, частичное, подтверждённое несоответствие, неизвестное и стоп-факторы. В текст не переносится свободное объяснение модели. Длинное резюме анализируется полностью по последовательным перекрывающимся фрагментам, с исходными координатами цитат и общим deadline. Фрагменты не меняют требования. Противоречащие подтверждения объединяются в unknown/contradictory; отсутствие сведений в одном фрагменте не опровергает подтверждение в другом. Лимит — 32 фрагмента; превышение даёт явную ошибку, а не незаметное удаление конца. Для новых полных оценок context_truncated=false, context_chunks содержит число запросов. Сохранённые старые результаты с context_truncated=true по-прежнему показывают предупреждение.

Backend повторно проверяет состав критериев относительно snapshot требований, веса, коэффициенты, цитаты по структуре и границам, принадлежность стоп-факторов, отсутствие двойного штрафа, диапазон, охват и итоговый балл. Объяснение повторно собирается из проверенных сравнений; свободный текст от отправителя не используется. Проверка цитат против самого текста выполняется анализатором; backend не получает полный извлечённый текст. Старые сохранённые оценки остаются читаемыми, но не приобретают задним числом статус проверенных.

## Проверка качества

Автотесты Мироновой и Москаленко основаны на фактах из аудита и являются синтетическими регрессиями. Исходные файлы этих кандидатов в текущей рабочей папке/БД не найдены. Эти тесты проверяют отсутствие переноса стека вакансии и арифметику стажа, но не являются независимой разметкой и не измеряют точность на реальных кандидатах.

Независимой разметки рекрутеров пока нет. Статус политики — `provisional`; качество не подтверждено. Проверка дословности цитат не гарантирует правильность смысловой интерпретации произвольного требования моделью. Консервативные проверки могут оставлять синонимы и неоднозначные условия неизвестными. Для приёмки нужны отдельно размеченные резюме и требования, включая спорные отрицания, образование, релевантность и пересекающиеся периоды работы.

Для сравнения подготовлен `scripts/evaluate-resume-quality.py`. Рекрутер размечает тестовую выборку до просмотра ответов модели; подбор правил проводится на другой выборке. Не удалять трудные случаи из отчёта. Команда:

```text
python scripts/evaluate-resume-quality.py --labels labels.jsonl --predictions predictions.jsonl --output metrics.json
```

Каждая строка `labels.jsonl`: `case_id`, `reviewer_id`, `independent: true`, `resume_text`, `rating` с `matched_keywords`, `triggered_stop_factors`, `criteria: [{id,status}]` и необязательным эталонным `score`. Каждая строка predictions: тот же `case_id` и полный `rating` анализатора. Все ID выборок должны совпадать, дубликаты и пустые выборки запрещены. Отчёт содержит precision/recall навыков и стоп-факторов, точность статусов, ошибки цитат, MAE балла и размеры выборок; при отсутствии знаменателя метрика равна `null`, а не «100%».


## Составные условия и уточнения для HR

Для явного И подтверждение всех частей даёт met; прямое несоответствие обязательной
части даёт not_met. Только нехватка длительности при подтверждённой нужной работе
даёт partial. Если часть подтверждена, а остальное неизвестно, — partial; если нет
подтверждений, — unknown. Для ИЛИ достаточно одной подтверждённой альтернативы,
а not_met требует опровержения всех. Неоднозначная логика даёт unknown.
Простые составные навыки И/ИЛИ дополнительно проверяются кодом.

Каждый unknown имеет unknown_reason из фиксированного списка: not_stated,
contradictory, not_relevant, unverified_evidence, future_intent,
incomplete_document, ambiguous_requirement. Для определённого статуса причина
не передаётся. HR видит причины и вопросы в раскрываемом блоке «Что уточнить»,
а не длинный автоматически раскрытый список неупомянутых навыков. Вопросы
формируются программой из проверенных статусов; они не меняют оценку и решение HR.

API независимо проверяет веса по нужной версии политики, причины, границы
цитат, объединение календарных месяцев и соответствие объявленных интервалов
датам в цитате. Backend не проводит новую смысловую оценку.

Для partial передаётся partial_reason: duration, learning или missing_parts.
При duration модель подтверждает нечисловые части требования, а программа
окончательно устанавливает числовой статус по проверенным месяцам: достаточный
стаж даёт met, недостаточный — пропорциональный partial. Причина missing_parts
не позволяет числу месяцев повысить весь критерий; коэффициент не выше 0,5
и не выше отношения подтверждённых месяцев к минимуму.
