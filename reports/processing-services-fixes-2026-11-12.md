# Исправления стажа, промпта, разделения сервисов и readiness

Повторная проверка и дополнительные исправления: [13 ноября](processing-services-recheck-2026-11-13.md).

Дата: 12 ноября 2026 года. Основание: первые четыре задачи из
[рекомендаций](processing-services-recommendations-2026-11-12.md).

## Что подтверждено и изменено

1. **Стаж.** До исправления новые регрессии воспроизвели принятие возраста и
   нерелевантной работы за подтверждённый опыт, выбор возраста вместо длительности
   работы и повышение `partial`/`not_met` до `met` по одному числу. Теперь число
   проверяется в контексте отдельного высказывания или датированной записи работы.
   Возраст, образование и сводный общий стаж не подтверждают релевантную работу;
   явно названные технологии проверяются в той же записи. Общий стаж остаётся
   верхним ограничением. Пересечения не суммируются, даты без явной длительности
   не переводятся в месяцы. Недостаточная связь даёт `unknown`, без подтверждённых
   `experience_months`. Проверка стоп-факторов длительности использует те же правила.
2. **Промпт.** Системные правила отделены от сериализованного JSON данных.
   Усилены требования к цитатам, возрасту/обучению, релевантности и составным
   условиям, неизвестным сведениям и инструкциям внутри резюме. Явно указано,
   что подтверждённый короткий релевантный опыт означает `partial`. Полнота ID
   ответа проверяется до расчёта; неизвестные/повторные/пропущенные ID дают
   ограниченный повтор, затем ошибку. JSON Schema берётся из `ModelRating`.
   Числа считает программа, `unknown` в объяснении — «Не указано» по категории.
3. **Самостоятельные сервисы.** `apps/resume-parser` и `apps/resume-evaluator`
   имеют отдельные Dockerfile, requirements и точки входа. Общий транспорт —
   `packages/processing-python`, документы/контакты — `packages/resume-documents`.
   У parser нет кода evaluator, сети модели, LibreOffice, python-docx, FastAPI
   или Uvicorn. Прежние Python HTTP/AMQP entrypoints, старый Dockerfile и runtime
   log удалены. Необходимые проверки перенесены в `tests/python`; тесты удалённых
   адаптеров заменены проверками текущего транспорта и интеграцией двух сервисов.
   Исторический TypeScript worker не включён в Compose и этим изменением не удалён.
4. **Готовность.** `/live` и совместимый `/health` проверяют жизнь процесса/потоков;
   `/ready` — оба broker-соединения и, для evaluator, доступность настроенной модели
   в Ollama. Отсутствие модели не делает parser неготовым. Во время подтверждённого
   отказа evaluator отменяет приём новых доставок; после успешной пробы возобновляет.
   Активные доставки сохраняют обычные правила ACK/reject/DLQ/deadline. API обоих
   режимов проверяет `/ready`; гостевой экран показывает недоступность отдельно от
   результатов задачи. Долгая работа исправной модели не считается отказом.

Контракты результата и `evidence-v1` сохранены. Исправлена согласованная проверка
Python/TS: числовая ветка не повышает частичное/отрицательное соответствие всего
составного требования. Если месяцы достаточны, но другое условие частично,
коэффициент `partial` — 0,5; при числовом недостатке используется отношение месяцев.
Веса, ID, штрафы и сохранённые старые оценки не меняются. Миграция БД не требуется.

## Проверки

- 95 Python-тестов: стаж/возраст/обучение, многострочные длительности, составные
  требования, промпт и бюджет контекста, PDF, контакты, транспорт, readiness,
  приостановка/возобновление consumers и отсутствие межзадачного кеша.
- 121 модульный TypeScript-тест; новые примеры Python проходят ту же TS-проверку
  арифметики/цитат, включая `partial`/`not_met` при достаточной длительности.
- `node tests/architecture.mjs`, `node tests/compose-architecture.mjs`,
  `git diff --check`; независимая сборка обоих Python-образов и frontend/API.
- В отдельном `hr-dam-processors-qa`: реальные parser/evaluator, гостевой режим
  без PostgreSQL/backend, затем авторизованный режим и сохранение оценок. PDF,
  DOCX, ZIP, ошибки отдельных элементов, пустой PDF, повтор при отказе модели.
  При отключении тестовой модели API показывает недоступность, parser выделяет
  два резюме, новых обращений к модели нет; после восстановления обе оценки
  завершаются без повторной загрузки. Доступность также проверена после входа.
  Ollama/ClamAV здесь транспортные фикстуры; контейнеры проекта удалены, тома сохранены.

## Реальная Ollama: сравнение четырёх конфигураций

Модель `qwen3.5:4b`, контекст 16384, лимит ответа 8192, температура 0.
Синтетические входы одинаковы; в профиле задан только один критерий опыта.

| Код / промпт | Возраст 23 года, электромонтажник, общий стаж 17 месяцев | Подтверждённые 15 месяцев коммерческой Python-разработки, минимум 36 |
| --- | --- | --- |
| Старый / старый | Ошибочно `partial`, 17 релевантных месяцев, 47,22 | `partial`, 15 месяцев, 41,67 |
| Старый / новый | Ошибочно `partial`, 17 релевантных месяцев, 47,22 | `partial`, 15 месяцев, 41,67 |
| Исправленный / старый | `unknown`, подтверждённых месяцев нет, 0 | Модель выбрала `not_met`, 15 месяцев, 0 |
| Исправленный / новый | `unknown`, подтверждённых месяцев нет, 0 | `partial`, 15 месяцев, 41,67 |

Проверка показывает необходимость менять и код, и инструкцию. Первоначальная
редакция нового промпта также возвращала `not_met` для короткого релевантного
опыта; явное правило `partial` добавлено и повторно проверено. Восемь результатов,
хеши системных промптов и параметры прогона сохранены локально в
`.qa/processing-before-after/model-results.json`; персональных данных там нет.
Скрипт: `tests/python/model_experience_smoke.py` с базовой версией исходников из Git.

## Применение и ограничения

Локальные образы пересобраны; перед заменой контейнеров в рабочих очередях обоих
режимов не было ожидающих или активных сообщений. PostgreSQL/S3 не пересоздавались.
После финального обновления все десять постоянных сервисов — `healthy`.
Через Nginx проверены гостевой статус и статус после входа сотрудника:
`available=true`, `model_ready=true`, `alive=true`. Диагностическая сессия завершена.

Это исправления конкретных дефектов и техническая регрессия. Независимая
разметка рекрутеров и измерение качества на отложенной выборке не выполнены.
Смысловая релевантность произвольных профессий не доказана: консервативные
лексические проверки могут оставлять синонимы и неявные связи в `unknown`.
OCR, суммирование опыта по календарным датам и атомарное дробление требований
не добавлялись. Закрытые гостевые задачи не возобновлялись, сохранённые оценки
не пересчитывались автоматически.
