# Реализация изменений оценки резюме

20 ноября 2026 года. Реализация плана `resume-evaluation-improvement-plan.md`.

## Что изменено

Новая политика `evidence-v4` согласована между Python и TypeScript. Старые версии остаются читаемыми; исходные оценки в БД не переписываются.

| Раздел плана | Реализация |
| --- | --- |
| P0: обязанности, отрицания, обучение | Общая проверка утверждений вместо буквального сравнения русских обязанностей. Отрицание относится к своему утверждению, «начальник» не означает начальный уровень. Инструменты и версии проверяются как идентификаторы. |
| P0: образование и квалификаторы | Неоконченное и запланированное образование не дают полного зачёта. Для полного зачёта сохраняются коммерческий характер и самостоятельность, если они требовались. |
| P0: стаж | Оператор, границы и месяцы хранятся раздельно. Поддержаны десятичные значения, диапазон, включённость границ. Сохраняется объединение пересекающихся периодов и защита от зачёта возраста/учёбы. |
| P0: стопы | Проверяются срабатывание и несрабатывание. Посторонняя цитата не даёт штрафа. Подавление дублей учитывает профессию и границу условия, а не только совпавшее число. |
| P1: условия | Исходные поля, обязательность, логика `all/any`, неоднозначность и точные дубли представлены явно. В формах есть предварительный разбор и предупреждения о возможных смысловых повторах. |
| P1: источник | Модель выбирает ID блоков; текст и координаты восстанавливает код. Обязанности выделяются по спискам и секциям. Для цитат доступны позиции и страницы. Контакты маскируются без смещения текста. |
| P1: поиск | Есть подсказки релевантных блоков, ограниченный повторный поиск и отдельная смысловая проверка спорных обязанностей. При ней можно выбрать другой исходный блок; замены через первое текстовое совпадение нет. |
| P1: документы | DOCX сохраняет порядок таблиц и абзацев. PDF сохраняет страницы. Нечитаемые страницы диагностируются, неоднозначное продолжение после служебного раздела не отбрасывается молча. Новый алгоритм колонок и OCR не включены без проверки. |
| P1: контекст | Условия обрабатываются группами. Сохраняются полный набор ID, общий дедлайн, причины завершения, токены и время. Конфликт отрицательного и частичного/полного подтверждения остаётся на уточнении. |
| P2: представление | Отсутствие обязательных условий отличается от низкой оценки. Показываются полнота сведений, уточнения, версия политики и причина пересмотра старого представления. Матрица и выгрузки используют общую оценку. |
| P2: воспроизводимость | Сохраняются digest/квантование модели, параметры, версии промптов и извлечения. Контрольные точки привязаны к версии модели и реализации. |
| P2: измерение | Скрипт качества проверяет наборы ID и считает матрицу ошибок, определённость отдельно от точности, срезы профессий/форматов, достаточность цитат по разметке, p50/p95, ошибки и устойчивость вариантов. |

## Регрессии и базовая линия

На одинаковых синтетических входах сравнились прежний код из Git и новая политика. Это проверка правил после заданного ответа модели, не измерение точности самой модели.

| Проверка | Прежнее поведение | Новое поведение |
| --- | --- | --- |
| Python в «Не знаю SQL, но работаю с Python» | `not_met` | `met` |
| SQL у начальника отдела | `partial` | `met` |
| Заявки на ремонт: изменение падежа | `unknown` | `met` |
| Техническое состояние транспорта: изменение формы слов | `unknown` | `met` |
| Сопроводительная документация | `unknown` | `met` |
| Коммерческий опыт по одному названию Python | `met` | `unknown` |
| Высшее образование не получено | `met` | `not_met` |
| План получения высшего образования | `met` | `unknown` |
| Два года против «до трёх» | `partial` | `met` |
| Три года против «не более двух» | `met` | `not_met` |
| Три года против «2,5» | `partial` | `met` |
| Отрицание о Python как стоп за транспорт | `triggered` | `unknown`, без штрафа |
| SQL как доказательство готовности к командировкам | `not_triggered` | `unknown` |

Проверки: **148 Python-регрессий, 134 TypeScript-теста и 7 тестов расчёта метрик**; архитектурные проверки приложения и Compose проходят. Фактический результат контрольного прогона дополнительно принят валидатором API.

Общие результаты Python сохранены в `tests/fixtures/evidence-ratings-v4.json`; TypeScript проверяет их независимо. Старые фикстуры v1/v2/v3 сохранены. Отдельные проверки покрывают исходные координаты, DOCX, неоднозначные служебные разделы, отсутствие критериев и защиту смысловой проверки от чужих ID/неподтверждённых квалификаторов.

## Модельные прогоны

Короткий синтетический пример прошёл через локальную Ollama: Python подтверждён, незнание SQL распознано, планы образования и отсутствующий коммерческий опыт не засчитаны, готовность к командировкам распознана. В одном из проверенных промежуточных вариантов он потребовал один запрос примерно на 11 секунд. Это не общий показатель производительности.

Проверялся исходный `resumes-first-10.pdf`, контрольный кандидат на страницах 29–31. Использовались **восемь условий**, выделенных для проверки пропущенных обязанностей, а не весь исходный профиль из плана. Проверялись `qwen3.5:4b` и отдельный вариант Q4_K_M; во время доработки менялись промпты и поиск, поэтому эти прогоны не являются чистым сравнением размеров или квантования моделей.

На модели из текущего `.env` в полном прогоне этого набора подтверждены заявки на ремонт, состояние транспорта, сопроводительная документация, выход техники, организация автоколонны, руководство водителями и дополнительное условие выхода техники. Закупки корректно оценены как частичное участие по подготовке заявок. В финальном прогоне все восемь статусов совпали с ожидаемыми для этого набора: семь `met`, один `partial`. Прогон занял 71,14 секунды; это наблюдение одного запуска, не p50/p95. Баллы этого уменьшенного профиля нельзя сравнивать с 57,47 или 85,07 из исходного плана.

Прогоны выполнялись напрямую без записи результатов в БД. Полные частные материалы лежат в игнорируемой `.qa`, рабочие логи не содержат резюме или промпты.

## Локальное применение

Собраны и обновлены `backend`, `guest-api`, `resume-parser`, `resume-evaluator` и `frontend`; контейнеры прошли проверки здоровья. Запущенный оценщик сообщает `policy=evidence-v4`, `/ready` возвращает 200, публичный API — `available=true`. Гостевой вход и доступность проверены через настоящий прокси приложения.

В Chrome проверены предварительный разбор, точные дубли, желательное образование, отчёты v4, отсутствие ложного нулевого балла при пустых условиях и мобильная ширина. Ошибок JavaScript нет. Проверки интерфейса использовали синтетические данные, не создавали задачи обработки.

В игнорируемом локальном `.env` исправлен адрес установленной на Mac Ollama: `http://host.docker.internal:11434` вместо отсутствующего контейнера `ollama`. Установлены проверенные локальные лимиты 8192/2048. Имя модели сохранено. Серверные значения `.env.example` не менялись. Очереди перед обновлением были пустыми; завершённые оценки не пересчитывались. Миграция БД для этих изменений не требуется: новая версия хранится в существующих JSON-деталях оценки.

## Что ещё нельзя объявить проверенным

1. Независимая отложенная выборка, размеченная HR, пока не предоставлена. Нельзя объявлять подтверждённую точность по профессиям и форматам или заменять разметку собственными синтетическими ответами.
2. Нужны согласованные пороги приёмки и честное сравнение моделей на одинаковой финальной версии кода, промптов и бюджете контекста. Промежуточные прогоны для этого непригодны.
3. Для смены порядка чтения многоколоночных PDF и включения OCR нужен отдельный набор документов с проверенным текстом. Текущий код диагностирует ограничения и не включает непроверенное преобразование.
4. Смысловые повторы и неоднозначные требования требуют проверки работодателем. Они помечаются до отправки; автоматически менять область условия или вес по похожим словам нельзя.

Политика остаётся `provisional`. Смысловой вывод модели может ошибаться даже при настоящей цитате. Подробный контракт и команды независимой проверки: [scoring-policy.md](../docs/scoring-policy.md).
