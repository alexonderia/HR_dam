# Базовые обработчики prepare/evaluate

Дата: 10 ноября 2026 года. Рабочая ветка: dev.

## Изменения

- `apps/resume-analyzer/app/processing_v2`: отдельный запуск текущего протокола.
  Один процесс операции использует два соединения с vhost, prefetch=1 на каждом
  и общую последовательную вычислительную ёмкость. Обработчики не публикуют
  сообщения, не объявляют очереди, не обращаются к PostgreSQL/S3.
- Команда и RS256 job-токен проверяются до выбора API. Проверяются операция,
  режим, идентификаторы, попытка, issuer/audience, permissions и deadline.
- Файл скачивается только с настроенного API; проверяются путь, размер и SHA-256.
  Рабочий каталог отдельный для job_id и удаляется после операции. Между
  заданиями отключён текстовый кеш прежнего извлекателя.
- Оценщик читает PDF/DOCX/DOC/RTF/TXT, использует существующие извлечение контактов,
  сравнение через Ollama и evidence-v1. Результат содержит ровно одну оценку на
  target и три агрегированных критерия; комментарии профиля/кластера разделены.
- Разборщик ограничивает ZIP по размеру/числу выходов, исключает небезопасные
  пути, шифрованные записи и симлинки. Ошибки отдельных элементов сохраняются
  вместе с пригодными резюме. Текстовый PDF разделяется по однозначным ФИО в
  заголовках страниц; сохраняются происхождение и номера страниц.
- `infra/processing/Dockerfile` собирает два образа, подключённых к профилю
  `processing`. У каждого GET /health и только публичные ключи job-токенов.
- HTTP result принимается до ACK. Временная ошибка возвращает команду через
  basic.reject(requeue=true), неверная команда отклоняется без повтора,
  закрытая задача подтверждается без выполнения.
- `GET input` дополнен необязательным `saved_result`: потеря confirm/ответа
  после сохранения результата восстанавливается повторным POST result без
  повторного разбора/оценки/загрузки выходных файлов.

Миграции и существующая БД не менялись. В основном окружении новые обработчики
не включались. Локальные образы собраны; запуск описан в `docs/preparation.md`.

## Проверки

- 17 Python-тестов: scoped JWT, повреждённая/чужая команда, expiry, HTTP статусы,
  SHA-256/размер/адрес скачивания, восстановление сохранённого результата,
  настоящий DOCX, лимиты и безопасные пути ZIP, PDF и повторяемые байты его выходов.
- 15 TypeScript-тестов `tests/processing-contract.test.ts`, включая сохранение
  первого результата и восстановление prepare после потерянного confirm.
- `node tests/architecture.mjs`, `node tests/compose-architecture.mjs` и
  `git diff --check` — успешно.
- `python3 tests/run_processors.py` — успешно. Отдельный Compose project,
  собственные volumes, порт 13100. Проверены реальные процессы обработчиков:
  DOCX; временный отказ модели и повтор команды; ZIP с двумя исправными и двумя
  неподдерживаемыми/повреждёнными элементами; PDF одного кандидата; сборный PDF
  двух кандидатов с продолжением страниц; PDF без текста; авторизованное
  сохранение резюме и оценок тем же оценщиком через второй vhost.
- Гостевые сценарии выполнены без backend и PostgreSQL. После тестов контейнеры
  и сети тестового проекта удалены, его volumes сохранены. Применены небольшие
  отдельные QA-подсети, чтобы не исчерпывать стандартные пулы Docker Desktop.

## Границы проверки

В сквозном тесте Ollama и антивирус заменены транспортными фикстурами. Разбор
документов и расчёт evidence-v1 настоящие, качество ответов реальной модели не
оценивалось. OCR не добавлен. Сканы, неоднозначные ФИО и границы внутри страницы
возвращают ошибку разделения. Для рабочего включения требуется проверка качества
на представительном наборе реальных документов и настроенной Ollama.
