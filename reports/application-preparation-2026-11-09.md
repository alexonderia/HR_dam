# Подготовка приложения к протоколу v2

Дата: 9 ноября 2026 года. Ветка: `front`.

Выполнена подготовка по разделам 1–4, 6–8 плана. Реализация разборщика и
оценщика остаётся в другой ветке; `apps/resume-analyzer` и `apps/worker`
не изменены. Их замена происходит на уровне нового Compose, где старые
worker/rank bridge не запускаются. Старые задания завершают до перехода на v2.

| Этап | Результат |
| --- | --- |
| Контракты | Строгие схемы v2, ошибки, критерии, результаты, технические события и синтетические фикстуры |
| Авторизация | RS256 cookie, серверные сессии, login/logout/refresh, CLI создания сотрудника, Origin, auth-check без БД |
| Nginx | Whitelist метод/путь, auth_request, закрытые старые/internal URL, потоковые запросы, JSON ошибки, независимый запуск |
| Гостевой контур | S3 CAS, cookie владельца, очередь допуска, ограничение загрузок, idempotency, отчёты, deadline и удаление |
| Оркестрация | Quorum queues/vhost, confirms/mandatory, стабильные задания, scoped job JWT, события/DLQ внутри API |
| Постоянный контур | Состояние и outbox в PostgreSQL, повтор неподтверждённых публикаций после рестарта, существующие правила сохранения кандидатов |
| Frontend | Выбор по /api/session, гостевая форма/отчёт, отдельные состояния ожидания/загрузки/обработки, вход/выход и сброс provider |
| Эксплуатация | Изолированные сети и credentials, два bucket, Compose secrets, очистка, постоянные backup без гостевых данных |

Миграции V1–V5 сохранены. Новая V7 содержит только авторизацию и постоянные
задачи/outbox. Проверки безопасности документов перенесены в независимый
модуль без бизнес-БД: сохраняются запреты активного PDF, вложений и макросов.
Архивы и сборные PDF передаются prepare, а не распаковываются backend.

## Проверки

- `npm run build` — успешно; Vite сообщает предупреждение о размере основного JS chunk.
- `npm test` — 80 тестов успешно.
- `npm run test:architecture` — успешно, включая отсутствие импорта бизнес-БД в guest/auth-check/processing/security.
- `docker compose config --quiet` и `git diff --check` — успешно.
- `npm run test:processing-v2` — успешно в отдельном project `hr-dam-v2-qa`.
- Nginx image: `http_auth_request_module` подтверждён, `nginx -t` проходит.
- Повторная подготовка окружения сохраняет существующие пары ключей.

Сквозной тест проверяет гостя при остановленных backend/PostgreSQL; реальные
конкурентные S3 create/CAS; права vhost и запреты публикации/чужой операции
обработчика; публикацию без маршрута; native delayed retry и delivery-count
через basic.reject; delivery-limit и учёт DLQ; prepare → N evaluate;
повтор output и result, частичный отчёт, чужую сессию, DELETE и поздний результат.
Проверено физическое удаление: в префиксе остаётся только техническая отметка,
без файлов, критериев и результатов.

Проверены отсутствие доступа через старые URL и проверочные location, сброс
поддельной/истёкшей cookie, 503 при отказе auth-check, независимость /health,
login/refresh/revocation, Origin, сохранение кандидатов/оценок и восстановление
outbox после остановки брокера и перезапуска backend. Браузерный тест проверяет,
что до входа нет запросов /api/app, а также вход/выход, мобильную ширину и ошибки JS.
Скриншоты: `.qa/processing-v2`; полный лог: `.qa/processing-v2-final.log`.

В QA используются синтетические протокольные peers и транспортный stub
антивируса. Основной Compose использует ClamAV. Качество распаковки/разделения,
извлечения и оценки, а также рабочие каталоги реальных обработчиков относятся
к другой ветке и проверяются после поставки её образов.

## Особенности включения

На проверенном RabbitMQ 4.3.0 валидатор policy не принимает delayed-retry-*;
настройки заданы как штатные x-delayed-retry-* queue arguments и проверены по
времени повторной доставки. SeaweedFS volume.max увеличен с 8 до 32 для двух
bucket. Публичный порт frontend подключён через отдельную edge-сеть; API,
PostgreSQL, S3 и RabbitMQ портов на хосте не имеют.

Инструкция запуска, создания сотрудника, подключения образов и перехода с v1:
[preparation.md](../docs/preparation.md). В основной базе тестовые пользователи
и задачи не создавались: проверки использовали отдельные volumes проекта QA.

При последующем развёртывании в основной БД обнаружена ранее применённая V6
`contact_provenance` из коммита `5751aa5`. Её исходный файл восстановлен из Git;
новая миграция авторизации перенумерована с V6 на V7. Существующая история БД
сохранена. Основной брокер уже использовал RabbitMQ 4.3.6, поэтому Compose
закреплён на 4.3.6 с сохранением имени узла. Подробности:
[отчёт о развёртывании](deployment-2026-11-09.md).
