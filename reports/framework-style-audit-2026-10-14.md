# Проверка фирменного стиля HR DAM

Дата: 14 октября 2026 года. Основа: Alabuga Framework 0.6.0.

Фреймворк был подключён корректно, но его оформление применялось частично.
Приложение переопределяло кнопки, поля, типографику и состояния собственным CSS,
а ряд компонентов вообще не использовал штатные классы. Исправления внесены
во все пять разделов интерфейса, общие компоненты, HTML-отчёт и оболочку
предпросмотра DOCX.

## На что опирается фирменный язык

Изучены живые примеры и справочник документации:

- [Начало работы](http://127.0.0.1:4176/index.html#start): контейнер `.af`, семантический HTML, одно основное действие.
- [Цвета и токены](http://127.0.0.1:4176/index.html#colors): роли текста, поверхностей, границ, действий и состояний вместо произвольных оттенков.
- [Типографика](http://127.0.0.1:4176/index.html#typography): Alabuga Sans для текста, Alabuga Heading для выразительных заголовков; основной текст 16 px, подписи 12 px.
- [Кнопки](http://127.0.0.1:4176/index.html#buttons): Primary, Secondary, Ghost и Clear; размеры 32/40/48 px и штатные состояния.
- [Формы](http://127.0.0.1:4176/index.html#forms): подписи, подсказки, обязательные поля, checkbox, switch, select и textarea.
- [Обратная связь](http://127.0.0.1:4176/index.html#feedback): фирменные фоны и читаемый текст уведомлений, округлые бейджи.
- [Диалоги](http://127.0.0.1:4176/index.html#dialog): нативный `dialog`, Escape и возврат фокуса.
- [Виджеты](http://127.0.0.1:4176/index.html#widgets) и [справочник классов](http://127.0.0.1:4176/index.html#classes): карточки, показатели, таблицы и прокрутка.

Наличие базового цвета в палитре не назначает ему роль в компоненте.
`deep` (`#000D3C`) не является основным акцентом и не определяет фон меню.
Основной акцент — `blue` (`#0C6FF1`). Меню использует светлую поверхность
`--af-bg-surface`, выбранный пункт — `--af-state-selected-bg` и `--af-text-link`.
Для таблиц выбран базовый светлый `af-table`; тёмный `af-table--corporate`
остаётся опциональным вариантом библиотеки, а не правилом оформления системы.

Сверены локальная браузерная сборка и [руководство интеграции](../FRAMEWORK_AGENT_GUIDE.md).
Для React-приложения подходит штатный режим HTML/CSS-компонентов: переход
на JSON-renderer не требуется. Поведение форм и маршрутов остаётся в React,
а фреймворк определяет их внешний вид.

## Что было исправлено

| Компонент | Найденное расхождение | Результат |
| --- | --- | --- |
| Заголовки страниц | Alabuga Sans с собственной толщиной и размером вместо Alabuga Heading | `af-heading`, фирменный шрифт Extra Bold; заголовки блоков `af-title` |
| Основной текст и подписи | Собственные размеры 8–13 px и многочисленные бледные оттенки | Основной текст из `.af`, подписи 12 px, цвета `--af-text-*` |
| Кнопки | `.app .af-btn` перекрывал шрифт, размеры и состояния; Secondary был серым | Удалены переопределения, используются штатные варианты и hover/active/disabled |
| Кнопки с иконкой и пагинация | Собственное оформление, маленькие области нажатия, текстовые стрелки | `af-btn--clear`, `af-btn--ghost`, `af-btn--sm`, иконки Lucide |
| Поля | Собственные рамки, радиусы, высоты и фокус | `af-input`; оформление приходит из библиотеки |
| Выбор и многострочный ввод | `af-input` использовался для всех типов | `af-select` и `af-textarea` |
| Подписи и подсказки | Собственные цвета, подсказки без штатного класса | `af-label`, `af-help`, `af-required`; сохранены связи с полями |
| Checkbox и switch | Собственные размеры, нарисованный переключатель | `af-check`, `af-checkbox`, `af-switch` |
| Уведомления и ошибки | Самостоятельные слабоконтрастные оттенки | `af-alert` и штатные модификаторы info/warning/danger |
| Статусы и теги | Прямоугольные плашки с собственной палитрой | `af-badge`, `af-badge--success`; дополнительные состояния через семантические токены |
| Карточки и показатели | Собственные радиусы и границы | `af-card`, `af-widget`, `af-metric__value`, `af-caption` |
| Таблицы | Собственная шапка, шрифт и отступы | Базовый `af-table` со штатной светлой шапкой, `af-table-scroll` |
| Раскрытая матрица | Длинные названия профилей накладывались друг на друга | Перенос текста в отдельных ячейках, сохранена горизонтальная прокрутка |
| Диалоги | Отсутствовали `af-dialog` и связь заголовка с диалогом | Штатные рамка, радиус, тень и backdrop; `aria-labelledby`, возврат фокуса |
| Навигация | Тёмная поверхность без подтверждённой роли, мелкие подписи; на планшете оставались только иконки без подписи | Светлая поверхность, штатные роли выбора, доступные названия ссылок и короткие мобильные подписи |
| Загрузка файла, очередь, рейтинги, журнал и этапы | Прикладные элементы с отдельными палитрами | Сохранены нужные структуры, оформление переведено на `--af-*` |
| HTML-отчёт и DOCX-предпросмотр | Arial и отдельный CSS; политика страницы запрещала подключение библиотеки | `.af`, штатные заголовки, таблица и уведомления; разрешены CSS своего приложения и встроенные шрифты |

Нейтральный и ошибочный бейджи — расширения приложения: в версии 0.6.0
нет штатных `af-badge--neutral` и `af-badge--danger`. Используются собственные
`badge--neutral` и `badge--danger` вместе с существующим `af-badge` и
токенами `--af-feedback-*`. Несуществующие классы фреймворка не добавлены.

В `apps/frontend/src/styles.css` нет прямых HEX-цветов. Все используемые
переменные `--af-*` и все классы `af-*` из компонентов найдены в локальной
библиотеке. CSS приложения задаёт композицию экранов и прикладные состояния;
размеры диалогов, адаптивные сетки, внутренние отступы контейнеров и печать
остаются задачей приложения.

## Проверки результата и ограничения

- `npm run build`: все приложения и пакеты собраны, проверка TypeScript пройдена.
- `npm test`: 20 тестов прошли.
- `npm run test:architecture`: проверка разделения приложений пройдена.
- В браузере проверены пять маршрутов при ширинах 320, 390, 768 и 1440 px.
  Переполнения страницы по горизонтали не обнаружено; широкие таблицы
  прокручиваются внутри своих контейнеров.
- Вычисленные основные стили кнопок, полей и checkbox сравнены с отдельным
  документом, подключающим только локальную библиотеку: расхождений нет.
- Проверены диалоги кандидата, резюме, кластера, профиля и записи чёрного
  списка, в том числе вложенный диалог и возврат фокуса к кнопке открытия.
- Проверены клавиатурный фокус, поиск, раскрытие таблицы, мобильная
  навигация, обязательные поля и отключение анимации при reduced motion.
- HTML-отчёт проверен через действующий API с его реальной политикой CSP:
  Alabuga Sans и Alabuga Heading Extra Bold загружаются, ошибок браузера нет.
- Отчёт выведен в PDF: подтверждён A4 landscape, а не глобальный формат
  презентации из CSS фреймворка.
- Локальные контейнеры frontend и backend пересобраны и запущены; оба healthy.

Проверка доступности не заменяет полный аудит WCAG и проверку со скринридером.
Новые записи в базу во время визуальной проверки не отправлялись. Успешная
загрузка нового резюме и все серверные состояния не воспроизводились заново.
Форматирование содержимого загруженных пользователем PDF не меняется.

Скачанный HTML остаётся читаемым без сервера благодаря небольшому резервному
оформлению. Полная фирменная типографика такого файла требует доступности
`/alabuga/alabuga.css`; без библиотеки используется системный шрифт.

Для последующих изменений сначала выбирайте существующий класс в справочнике,
затем оформляйте отсутствующие прикладные элементы через смысловые токены.
Переопределение общих `.af-btn`, `.af-input`, `.af-badge` и `.af-dialog`
в CSS приложения снова создаст расхождение с библиотекой.
