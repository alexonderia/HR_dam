# Обновление Alabuga Framework в HR_dam

Дата: 9 ноября 2026 года. Версия: **0.6.0 → 1.3.1**.

## Источник

`https://framework.acom-offer-desk.ru/` недоступен из среды проверки:
системный DNS возвращает timeout, Chrome — `ERR_NAME_NOT_RESOLVED`.
Проверить опубликованную на сайте версию не удалось.

По выбору пользователя установлена **1.3.1 — подготовленный кандидат выпуска**,
а не опубликованная локально 1.1.0. Использованы готовые файлы из соседнего
репозитория `alabuga-framework/artifacts/release-1.3.1/standalone`.
HEAD исходного репозитория: `4f2a74cc191b22682b9bc7f61de4ee9ecb7cecb9`.
SHA-256 обоих файлов совпали с `acceptance.json` пакета и ответами работающего
фронтенда после обновления.

| Файл | SHA-256 |
| --- | --- |
| alabuga.css | `28b4fe3fd67e9058ce708b3c5cf7215e31335ac8d7fa04fed68677d0f2d5948e` |
| alabuga.iife.js | `7e49a0be31f3b083396d6cb72161100048e9c202306debb6b0d6d1b102d44f22` |

## Изменения

- Заменены готовые JS/CSS; сведения о поставке сохранены в
  `apps/frontend/public/alabuga/release.json`.
- В адреса обоих файлов добавлена версия `?v=1.3.1` для обновления кеша браузера.
  Для готовых файлов закреплены окончания строк LF в `.gitattributes`.
- Обновлён `FRAMEWORK_AGENT_GUIDE.md`: самостоятельная поставка, схема 1–5,
  новые публичные API, пути материалов и поведение Select.
- Диалог получил собственный корень `.af`: поля окна входа сохраняют корректные
  размеры и не выходят за границы.
- Размещение фильтров и кода страны телефона учитывает новую обёртку
  `.af-select-box`; поле телефона сохраняет место для ввода на узком экране.
- Используемые приложением фирменные изображения совпадают с новой поставкой
  и не требуют замены.

## Проверки

`npm run build -w @hr/frontend` завершён успешно: TypeScript и production-сборка.
Vite сообщает о размере основного JS-чанка более 500 kB; это предупреждение
не препятствует сборке.

До развёртывания и после него выполнены 32 браузерные проверки:
гостевая форма, окно входа и шесть рабочих разделов на ширинах 1440, 390 и
320 px; изменение фильтра через React, выбор кода страны с клавиатуры,
отсутствие горизонтального переполнения страницы и выхода полей за диалог.
Загрузка изображений успешна, ошибок JavaScript и HTTP-ошибок ресурсов нет.
`window.Alabuga.VERSION` возвращает `1.3.1`.

Гостевая страница проверена с настоящим `/api/session`. Рабочие разделы
проверены с синтетическими ответами API в браузере: сотрудники и задачи в
основной БД не создавались, запросы на изменение данных не отправлялись.

## Развёртывание

Обычная Docker-сборка остановилась при загрузке `nginx:stable-alpine`:
DNS для `registry-1.docker.io` также недоступен. Для текущего развёртывания
создан образ из уже работавшего локального runtime с Nginx 1.30.6 и готовой
проверенной production-сборки. Старые статические файлы удалены внутри нового
слоя образа перед копированием новых. Конфигурация прошла `nginx -t`.
Основной Dockerfile сохранён для обычной сборки при доступном реестре.

Обновлён только контейнер frontend:

```powershell
docker compose -p hr_dam up -d --no-deps --no-build --wait --wait-timeout 60 frontend
```

Сравнение ID контейнеров подтвердило, что остальные семь сервисов не
пересоздавались. Все восемь основных сервисов healthy.
`http://localhost:3000/` обслуживает новую версию.

Проверки HTTP: `/health` и `/api/session` — 200;
`/api/app/overview` без входа — 401; прежний `/api/overview` — 404.

`hr-dam-frontend:before-framework-1.3.1-20261109`. При необходимости откат
запущенного фронтенда выполняется без пересоздания остальных сервисов:

```powershell

docker compose -p hr_dam up -d --no-deps --no-build --wait frontend
```

Этот откат меняет только работающий образ; исходные файлы новой версии
остаются в рабочем дереве.
