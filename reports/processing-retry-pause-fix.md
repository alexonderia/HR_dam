# Паузы между попытками анализа

20 ноября 2026 года.

Причина: попытка выполнения ограничена 840 секундами. После временной ошибки процессор возвращает сообщение в очередь. Раньше первоначальный work_deadline продолжал идти в очереди, а интерфейс показывал задание как непрерывно анализируемое.

## Изменения

- Каждый запуск получает run_id. Перед повторной доставкой процессор отправляет waiting_retry, в том числе при штатном завершении контейнера.
- API хранит сумму активных отрезков work_elapsed_ms и момент начала текущего отрезка. Пауза снимает текущий work_deadline; очередь ограничена отдельным прежним сроком.
- Новый запуск получает только остаток исходного бюджета. 14 минут анализа + два часа ожидания оставляют 16 минут, а не новый полный бюджет и не истёкший срок.
- Старые сообщения не могут поставить на паузу текущий запуск, заменить его результат или дописать контрольные точки.
- Контрольные точки сохраняются. Код расчёта оценок, промпты, модель и контекст контрольных точек не менялись.
- При аварийном исчезновении процесса без уведомления сохраняется дедлайн активного отрезка: зависшее вычисление не получает бесконечный бюджет.
- Ожидание повтора показывается отдельно от анализа; время анализа и итоговая длительность учитывают только активную работу для новых запусков.

## Проверки

150 тестов TypeScript, 167 тестов Python. Проверены паузы на два часа и час между отрезками, остаток бюджета, защита от сообщений старого запуска, контрольные точки, статусы API и неизменность таймера в очереди. Сборка пяти контейнеров завершена. Проверка в Chrome подтвердила: только текущий файл находится в списке активного анализа; файл на паузе показывает 5/8, ожидание повторного запуска и зафиксированные 14 минут. Проверены ширины 1280 и 390 пикселей.


## Применение

Обновлены backend, guest-api, resume-parser, resume-evaluator и frontend. При обновлении текущая незавершённая обработка поставлена на паузу с сохранением пяти контрольных точек и уже использованного бюджета; после запуска нового процесса пять точек успешно восстановлены. Промпты и версия вычисления контрольных точек не изменялись.

`resumes-first-10-18-20.pdf` к моменту проверки уже завершился успешно. Для `resumes-first-10-4-8.pdf`, завершившегося старым таймаутом, поставлена новая попытка из сохранённого файла (`19836eae-c0f2-4311-83d8-cca2fc7c3e06`). В неё включены шесть текущих активных проверочных профилей; прежние отключённые кластеры остались отключёнными. Новая попытка ожидает очереди, её завершение не объявляется состоявшимся.
