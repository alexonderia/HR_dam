# Составное отчество: результат отклонялся API

Дата отчёта: 11 ноября 2026 года. Исходный пакет от 10 ноября:
`5f9520e3-2bff-4470-9acf-c6f229a673ba`, 52 резюме.

## Подтверждённая причина

Оценщик правильно извлекал составное отчество из двух слов. Общий контракт
`contactsResponseSchema` искал значение каждого поля ФИО среди отдельных слов
цитаты. Поэтому полное составное отчество не совпадало ни с одним словом,
результат API отклонялся, а команда переходила в DLQ. Обработчик DLQ показывал
общее сообщение «Не удалось завершить обработку. Отправьте файлы заново».

Проверка контактов всех 52 резюме до исправления выявила ровно два отказа:
№13 (страницы 40–43) и №52 (страницы 165–167), оба по `candidate.middle_name`.
После исправления все 52 набора контактов принимаются.

## Исправление

`packages/contracts/src/domain.ts` проверяет значение имени как последовательность
полных соседних слов в цитате. Сохраняются нормализация регистра/«ё», границы
слов, порядок частей и запрет неподтверждённых значений. Телефонная проверка
не менялась. Контракт используется гостевым и авторизованным API; оба образа
пересобраны и установлены. Схема БД и сохранённые оценки не менялись.

## Проверки

- До изменения новый тест воспроизводил отказ на составном отчестве.
- После изменения прошли 34 теста: `contacts.test.ts`,
  `processing-contract.test.ts`, `evidence-ratings.test.ts`.
- Новые проверки подтверждают приём составного отчества через контракт результата,
  в том числе при переносе строки и другом регистре. Другой порядок слов,
  посторонние слова между частями и совпадение лишь части слова отклоняются.
- Все 52 реальных набора контактов проверены в памяти, без вывода ФИО и цитат.
- Реальное резюме со страниц 40–43 прошло гостевой сценарий с исходными
  критериями и настоящей моделью: одна оценка, ошибок нет, составное ФИО сохранено,
  18 секунд. Технический результат: `.qa/compound-name-check.result.json`.

## Итог исходного пакета и повторная отправка

При обновлении API на машине с высокой нагрузкой возник период его временной
недоступности. Три последних задания также завершились ошибкой доставки.
Исходный пакет закончил работу с 48 успешными и четырьмя неудачными оценками:
страницы 40–43, 158–160, 161–164 и 165–167. Уже закрытые гостевые задания
не переписывались и не возобновлялись.

К 11 ноября старый гостевой отчёт штатно очищен по сроку хранения. Из локального
исходного PDF подготовлен архив только четырёх неудачных резюме:
`.qa/retry-failed-4-5f9520e3.zip`, права 0600, исключён из Git и Docker context.
Для проверки исправления используется новая отдельная гостевая сессия и
контрольные критерии; это проверка обработки, а не восстановление старых баллов.

После ночного перерыва дополнительный контрольный запуск выявил остановленную
нативную Ollama: все четыре задания получили `ModelUnavailable`. Запущено
установленное приложение Ollama, из оценщика подтверждены HTTP 200 на `/api/tags`
и наличие настроенной модели. Контрольный пакет повторно отправлен после запуска.

Повторная проверка завершена успешно: задача
`9e73ba7d-8168-4d9d-bed4-b3f600658553`, четыре кандидата, четыре готовые оценки,
ошибок нет, 161 секунда. Фамилии, имена и составные отчества всех четырёх
совпали с исходными PDF. Результат проверки сохранён в
`.qa/compound-name-batch-check.result.json`. Только диагностическая задача
удалена штатным DELETE; архив для пользовательской повторной отправки сохранён.
